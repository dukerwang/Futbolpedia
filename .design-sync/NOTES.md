# design-sync notes — Futbolpedia

## Not a real design system

This repo is the Futbolpedia AI application itself, not a published component
library. `components/` holds ~12 app-specific React components with no
build/dist, no `.d.ts` output, no Storybook, and no package `main`/`module`/
`exports` entry. The user explicitly chose to sync these app components
anyway (2026-07-02) after being told this mismatch exists.

Consequences:
- The converter runs in **synth-entry mode** (`[NO_DIST]`): `--entry ./dist/index.js`
  is passed deliberately pointing at a path that never exists (vite only emits
  hashed app bundles, never a stable `dist/index.js`) so `resolveDistEntry`
  soft-fails and the converter synthesizes an entry from `components/*.tsx`
  instead. There's no real `buildCmd` to run for the JS bundle itself — only
  the Tailwind CSS step below needs building.
- Several components are tightly coupled to `App.tsx` state (callbacks,
  conversation/profile objects, `useState`/`useEffect` wiring) — notably
  `SidePanel.tsx` (~37KB) and `ConversationsPanel.tsx`. Their previews are
  compositions with realistic mock props/handlers, not literal reproductions
  of how `App.tsx` wires them.

## Styling: no compiled stylesheet exists

The app styles itself via the **Tailwind CDN script** (`cdn.tailwindcss.com`)
with a custom inline `tailwind.config` in `index.html` (colors: `cream`,
`charcoal`, `emerald`; fonts: `serif`=Playfair Display, `sans`=Inter,
`mono`=JetBrains Mono). This JIT-compiles classes at runtime in the browser —
there is no static CSS file anywhere in the repo (`/index.css` is referenced
in `index.html` but does not exist on disk).

Fix: `.design-sync/tailwind.config.cjs` + `.design-sync/tailwind-input.css`
reproduce that exact theme and compile a real static stylesheet via
`cfg.buildCmd` (Tailwind CLI) into `.design-sync/tailwind-output.css`
(gitignored — regenerated by `buildCmd`, same as any other build output),
wired in as `cfg.cssEntry`.

**Re-sync risk**: if `index.html`'s inline `tailwind.config` block or the
`<style>` block (scrollbar/`.prose` rules) changes, `.design-sync/tailwind.config.cjs`
and `.design-sync/tailwind-input.css` must be updated to match by hand — they
are not derived automatically from `index.html`. Check this on every re-sync.

Google Fonts (Inter, Playfair Display, JetBrains Mono, Material Symbols
Outlined) are pulled in via `@import` at the top of `tailwind-input.css` —
these surface as `[FONT_REMOTE]` (informational, loads at runtime from
Google's CDN, no local font files needed).

## Re-sync risks (forward-looking)

- No dist/build for the component bundle itself — if this repo ever gets a
  real library entry point, remove the synth-entry workaround and point
  `--entry` at it for a stronger `.d.ts` contract.
- Tailwind theme is hand-mirrored (see above) — will silently go stale if
  `index.html` changes and this file isn't updated.
- Preview compositions for state-coupled components (`SidePanel`,
  `ConversationsPanel`, `ChatHistory`) use mock data/handlers, not real app
  state — verify they still match real usage after significant `App.tsx`
  refactors.
