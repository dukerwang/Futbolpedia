# Gaffa Q&A in Futbolpedia — Implementation Plan

> **For agentic workers:** Implement task-by-task. Checkboxes track progress. Spec is the source of truth.

**Goal:** Ship Phase 1 Gaffa mode in Futbolpedia chat — dedicated prose path with curated rules snapshot, soft auto-detect nudge, and Phase 2 context-bag stubs. No live league connect.

**Source of truth:** `docs/superpowers/specs/2026-09-06-gaffa-qa-design.md`

**Repo:** `/Users/dukewang/Futbolpedia` only (Gaffa `USER_GUIDE.md` is read as input for the snapshot; do not modify Gaffa in Phase 1).

**Tech stack:** React, TypeScript, existing `@google/genai` chat/search patterns in `services/geminiService.ts`.

## Resolved plan choices (from spec open items)

| Choice | Decision |
|---|---|
| Persist Gaffa mode | Per **conversation** — add `domain` on `Conversation` |
| default/fast in Gaffa mode | Keep speed toggle; it controls **research intensity** only (no dossier branch) |
| Module layout | `constants/gaffaRules.ts` + `services/gaffaChatService.ts` + types in `types.ts` |
| Auto-detect list | Small high-precision set; prefer misses over false positives |

## Global constraints

- Gaffa mode **never** calls `synthesizeFormalResponse` / dossier `responseSchema`.
- Do not inject Gaffa rules into `MASTER_INSTRUCTION_SET` / `getMasterInstructions`.
- Do not invent roster, standings, market prices, or commissioner overrides.
- Scoring-data firewall: no fantasy points / private match ratings as football-quality evidence.
- Banned meta phrasing in answers: “in Gaffa”, “in Gaffa terms”, “from an FPL perspective”.
- Snapshot is common defaults; prompt must note commissioner settings may differ.
- `npx tsc --noEmit` must pass before declaring done.

## Task 3: Auto-detect helper

**Files:** `services/gaffaDetect.ts`

- [ ] Export `looksLikeGaffaQuestion(message: string): boolean`.
- [ ] High-precision cues only (case-insensitive), examples:
  - `\boop\b` / `out[- ]of[- ]position`
  - `auto-?sub` + position language, or `bench cover`
  - `\b(academy|injured reserve|\bIR\b)\b` in roster sense — be careful; prefer multi-signal
  - `€\s*\d` / `\d+\s*m\b` with `trade` / `auction` / `bid`
  - `formation lock` / `player lock`
  - `\bgaffa\b` explicit
- [ ] False-positive guard: alone, words like “academy” or “trade” for real-world football should **not** trip unless paired with another Gaffa cue or explicit “gaffa”.
- [ ] Export a tiny list of self-check strings in a comment or `GAFFA_DETECT_EXAMPLES` for manual QA.

**Done when:** “Can a CB auto-sub for an LB?” → true; “Rate Haaland” → false; “Isak for Jackson + €70m” → true if trade+€m paired.

## Task 4: `sendGaffaMessage` pipeline

**Files:** `services/gaffaChatService.ts`  
**Reuse:** search / chat helpers from `geminiService.ts` — prefer importing existing exports; if `sendChatMessage` is not exported, either export a prose-only helper or duplicate the minimal chat send with `parseStructured: false`.

- [ ] Export:

```ts
sendGaffaMessage(
  message: string,
  history: ChatMessage[],
  options?: {
    speed?: 'default' | 'fast';
    imageData?: string;
    contextBag?: GaffaContextBag;
  }
): Promise<string>
```

- [ ] Always return `string` (never `PlayerProfile`).
- [ ] Classify turn: `rules` | `strategy` | `player_trade` via light heuristics:
  - Player names / “trade” / “vs” / “worth” / “sell” / “buy” for assets → `player_trade`
  - Pure mechanics keywords → `rules`
  - Else → `strategy`
- [ ] Build system instruction via `buildGaffaSystemInstruction()` + locked context bag block (`connected: false` caveat).
- [ ] For `rules`: answer with snapshot; skip or minimize search.
- [ ] For `player_trade` / football-heavy `strategy`:
  - `fast`: 1–2 targeted searches then prose
  - `default`: slightly deeper search (2–3) then prose
  - Pass factual foundation into the user prompt; do not use fantasy points as evidence
- [ ] Call chat with Gaffa system instruction and **`parseStructured: false`** (or equivalent) so dossier JSON parsing cannot fire.
- [ ] On failure: throw a clear Error string for App to show as Editor's Note.

**Done when:** Calling `sendGaffaMessage("Can a CB cover LB on the bench?", [])` returns prose mentioning strict eligibility; calling with “rate Isak” returns prose, not a profile object.
